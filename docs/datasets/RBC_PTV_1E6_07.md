README называет набор DNS test case кубической Rayleigh--Benard convection при

## Фактическая структура

```text
files: Points_1E6_07_00000.npz ... Points_1E6_07_00010.npz
key: data
columns: t, x, y, z, u, v, w, T, p
```

Каждый файл имеет shape `(262144, 9)` и dtype `float64`. `262144 = 64^3`.
Общий объединенный набор имеет `2,883,584` строк.

Координаты `(x,y,z)` совпадают между всеми 11 временами и образуют регулярную
сетку `64 x 64 x 64`. Поэтому публичный test case фактически является временной
последовательностью полей на неподвижной эйлеровой сетке, несмотря на `PTV` в
имени. В нем нет `PartID` и нет лагранжевых траекторий.

Reference preprocessing `makedata_testcase.py` только объединяет строки и делит
их на `inputs=(t,x,y,z)` и `outputs=(u,v,w,T,p)`. Дополнительной нормировки этот
скрипт не выполняет.

## Физическая размерность и обезразмеривание

Статья задает безразмерную систему:

```text
x* = x / L
u* = u / U_ff
t* = t / (L / U_ff)
T* = (T - T_mean) / DeltaT
p* = p / (rho U_ff^2)
U_ff = sqrt(alpha g DeltaT L)
```

и решает PDE с коэффициентами `nu*=sqrt(Pr/Ra)` и
`kappa*=sqrt(1/(Pr*Ra))`.

Диапазоны test case и reference equations подтверждают, что raw NPZ уже находится
в этой безразмерной системе: пространство `[0,1]^3`, T в `[-0.5,0.5]`, скорости
порядка free-fall scale. Повторное физическое обезразмеривание не требуется.

Оригинальный repository не дает достаточных физических `L`, `DeltaT`, `rho`,
`alpha` для обратного перевода именно test case `Ra=1e6`, `Pr=0.7` в SI. Значения
`L=300 mm`, `U_ref≈50 mm/s`, `t_ref≈6 s` из статьи относятся к ее
`Ra=1e9`, `Pr=6.9` случаю и не должны переноситься сюда без отдельного источника.

## Решение для EXP-001

Для TensorFlow--PyTorch parity использовать значения без изменений:

```text
input coordinates: original t,x,y,z
field values: original u,v,w,T,p
training dtype: explicit float32 after loading
Ra: 1e6
Pr: 0.7
gravity axis: z
```

Не применять min-max, z-score и remapping времени. Любое affine преобразование
координат изменяет производные. Например, при `x_hat=(x-a)/s`:

```text
d/dx = (1/s) d/dx_hat
d2/dx2 = (1/s^2) d2/dx_hat2
```

Без этих множителей исходные PDE residuals становятся другой задачей.

T,p не участвуют в data loss. Они доступны для evaluation. Давление в raw test
case имеет ненулевой offset около `0.488`, несмотря на общее утверждение статьи о
центрировании pressure. Поскольку momentum определяет только `grad(p)`, pressure
metrics должны выполнять gauge alignment отдельно для каждого времени. Для
parity нельзя молча вычитать offset из входного файла.
